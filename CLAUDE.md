## Project Overview

A personal productivity mobile app (iOS-first, React Native) for managing goals and tasks across time horizons (daily / weekly / monthly / one-time). Users earn points for completing tasks and spend them on self-defined rewards (luxury items, treats, etc.).

## Tech Stack

| Layer | Choice | Rationale |
|-------|--------|-----------|
| Framework | React Native + Expo (managed workflow) | Fast iteration, good iOS tooling, easy Android extension later |
| Language | TypeScript (strict) | Type safety for complex domain models |
| Navigation | Expo Router (file-based) | Integrates well with Expo, supports deep linking |
| State / Store | Zustand | Lightweight, no boilerplate, easy slices per domain |
| Local DB | expo-sqlite + Drizzle ORM | SQLite is offline-first; Drizzle gives type-safe queries |
| Styling | NativeWind (Tailwind for RN) | Consistent design tokens, fast iteration |
| Notifications | expo-notifications | Scheduling task reminders |
| Testing | Jest + React Native Testing Library | Unit and component tests |

## Core Domain Model

### Task vs Goal distinction
- **Task** — atomic, schedulable unit of work that completes in one sitting. Earns points on completion.
- **Goal** — longer-horizon objective (weekly / monthly). Contains one or more tasks. Earns bonus points when all child tasks are done.

### Schedule Rules (`src/lib/recurrence.ts`)
Recurrence is stored as a JSON rule object (inspired by RRULE):
```typescript
type ScheduleRule =
  | { type: "once"; date: string }            // ISO date
  | { type: "daily"; startDate: string }
  | { type: "weekly"; daysOfWeek: number[] }  // 0=Sun … 6=Sat
  | { type: "monthly"; dayOfMonth: number }
  | { type: "custom"; intervalDays: number; startDate: string }
```
Use `lib/recurrence.ts` to compute `nextDueDate(rule, lastCompleted)` — keep all recurrence logic here, not scattered across components.

### Points Economy
- Each task has a `pointValue: number` set at creation.
- Completing a task → `points.balance += task.pointValue`.
- Rewards have a `pointCost: number`; redeeming deducts from balance.
- Point transactions are append-only (never delete) for history.

### DB Schema key tables (`src/db/schema.ts`)
```
tasks          id, title, categoryId, scheduleRule (JSON), pointValue, isGoal, parentGoalId
completions    id, taskId, completedAt
points_ledger  id, delta, reason, taskId?, rewardId?, createdAt
categories     id, name, color, icon
rewards        id, name, description, pointCost, imageUri?, redeemedCount
```

## Architecture Decisions

- **Offline-first**: all data in local SQLite. No backend required (Phase 1). Cloud sync is a future concern.
- **Single source of truth**: DB schema in `src/db/schema.ts`. Zustand stores are read-through caches of DB state — they do not own persisted data.
- **Recurrence is computed, not stored**: `nextDueDate` is always derived from the rule + last completion; do not store a mutable "next due" field in the DB.
- **No soft deletes for completions**: completions are facts; only tasks/rewards can be archived (`archivedAt` timestamp).
- **Points ledger is immutable**: transactions are inserted, never updated/deleted. Balance = `SUM(delta)` over the ledger. Uncompletions are negative-delta entries, not deletions.
- **Task = Goal**: Goals are tasks where `isGoal = true`. Child tasks link to a goal via `parentGoalId`. Goals earn `bonusPoints` when all children are completed in a day.
- **Goal bonus guard**: `pointsStore.wasGoalBonusGrantedToday(goalId)` checks the ledger before granting a bonus — prevents double-awarding on re-completion.
- **`npm install` always needs `--legacy-peer-deps`** (or `.npmrc` already sets it) due to an expo-router / react-dom peer dep gap.

## Key Flows

### Task completion (Today screen / Goal detail)
1. `taskStore.completeTask(taskId, forDate)` → inserts row in `completions`, updates `completedTodayIds`
2. `pointsStore.addPoints(+pointValue, 'task_complete', { taskId })` → inserts in `points_ledger`
3. If task has `parentGoalId` → check if all siblings done → if yes (and bonus not yet granted today) → `addPoints(goal.bonusPoints, 'goal_bonus', { taskId: goalId })`
4. Haptic feedback via `expo-haptics`

### Points redemption (Rewards screen)
1. Check `balance >= reward.pointCost` (alert if not)
2. `rewardsStore.redeemReward(rewardId)` → increments `redeemedCount`
3. `pointsStore.addPoints(-reward.pointCost, 'reward_redeem', { rewardId })` → negative ledger entry

### DB migrations
- Edit `src/db/schema.ts`, then run `npm run db:generate`
- The generated `src/db/migrations/migrations.js` is imported in `app/_layout.tsx` and applied at boot via `useMigrations()`
